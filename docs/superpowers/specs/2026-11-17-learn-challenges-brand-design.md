# Learn, Challenges and brand redesign

Date: 2026-11-17. Branch: `design/learn-challenges`, stacked on `design/overhaul` (PR #21).
Status: draft, waiting for approval. Nothing is built yet.

## Intent

The Learn catalog reads as a wall of identical cards, the Challenges page is lopsided, and the
site's controls feel static. The owner wants both pages to feel designed by a person: a guided
path through the course with an illustration per section, a balanced Challenges page with a
visual streak, livelier buttons, a new logo and mascot, and sixteen named craft details applied
wherever they fit.

## Goals

1. A first-time learner can tell within one screen where to start, how far they are and what is next.
2. Each of the four course groups has its own full-color illustration in the mascot's style.
3. The Challenges page is visually balanced, each challenge is one simple bar, and the streak is a
   bar plus a calendar plus the basic stats.
4. Every button gives press, hover and focus feedback that feels physical and can be interrupted.
5. The new logo and mascot replace the current mark everywhere it appears.
6. The sixteen craft details (section G) are each applied and checkable.

## Non-goals

- No change to lesson content, exercises, grading, scoring, challenge selection or the puzzle workspace layout.
- No animation library. No new font files.
- No shared element transition into the puzzle workspace (it renders per request and Monaco must not animate).

## Anti-goals

- Motion that loops, floats or bounces (the one bounce stays the correct-result check).
- Anything that sends answer keys, unrevealed hints or a browser-computed score to the client.
- Showing "correct" before the server has graded.
- Layout that shifts when progress, countdowns or images load.
- A landing page that needs the database.

## Constraints from the project rules

- Colors in components come from theme tokens. Two stated exceptions are introduced here, both
  owner decisions: the mascot's fixed colors and the illustration plates.
- Motion goes through the tokens and keyframes in `web/app/globals.css`, stays finite and is off
  under reduced motion. Never animate Monaco, tree targets, editor tabs or splitters.
- Icons come from `Icon.tsx`. Labels are sentence case. Monospace is only for code, paths and IDs.
- `LocalRotation.tsx` stays the one place a local-zone time is shown.
- The brand files are generated by `web/scripts/brand-icons.mjs` and checked by `web/tests/landing.test.ts`.
- The theme catalog is generated; removal goes through the derivation, never a hand edit.
- US English. Empty and error states say what happened and what to do next.

## Approaches considered

1. **Native CSS plus React's built-in `ViewTransition` (chosen).** CSS transitions retarget when
   interrupted, the motion tokens already exist, and React 19.3 exports a stable `ViewTransition`
   that Next 16.4 animates on route changes with no config flag. No bundle cost.
2. **Add the Motion library.** Gives springs and layout animation, but adds a second motion system
   beside `globals.css` and client JavaScript to static pages. Rejected.
3. **Hand-rolled `document.startViewTransition` on link clicks.** Works, but duplicates what React
   now does and fights Next's router. Rejected.

For images, the owner chose full-color illustrations on fixed plates over theme-tinted line art,
and chose to remove the themes that clash with the plates.

## The design list

### A. Brand: logo and mascot

Reference: `Codebases Mascot Brand Identity.png` at the repo root (the owner's lossless file, 1774 by 887), with a copy at `docs/superpowers/specs/assets/logo-mascot-reference.webp`.

- A1. Redraw the mascot as hand-built SVG in two forms: **head** (cap with the `</>` badge, face,
  arms on the cap, two spark lines) and **full** (seated, holding the magnifier with `</>`).
- A2. Geometry lives in `web/components/site/mascot.ts`, replacing `mark.ts`. `web/app/opengraph-image.tsx` and `web/tests/landing.test.ts` import from `mark.ts` today and move to the new module in the same change; the social preview image shows the new logo. `Logo.tsx` stays
  the one logo: head plus the word "codebases"; `variant="mark"` shows the head alone.
- A3. The wordmark is drawn as SVG paths in the rounded bold lettering of the reference and filled
  with `currentColor`, so it follows each theme's text color.
- A4. Mascot colors are fixed and defined once, each as an OKLCH value with its hex equivalent beside it (the preview image and the PNG output need hex), as custom properties (periwinkle body, mint
  accents, navy outline, white face, blush). In dark schemes a 1.5-unit light edge sits behind the
  navy outline so the figure stays readable.
- A5. `brand-icons.mjs` is rewritten to emit `app/icon.svg` (head only, simplified: no sparks, no
  blush below 32px), `app/apple-icon.png`, and `public/brand/{mark,logo}-{light,dark}.svg`. The
  brand tests are updated to check the new geometry.
- A6. A `Mascot.tsx` component renders the full form. It appears in the Learn header, the
  signed-out Challenges panel, and the Learn "all complete" state. It is decorative (`aria-hidden`).
- A7. The mascot never animates in a loop. On the Learn header it may play `motion-enter` once.
- A9. Likeness gate: there is no vector source, so the redraw is shown to the owner beside the
  reference before Learn and Challenges use it. Those pages build against the `Mascot` component's
  box in the meantime.
- A8. Optical centering: the head sits 1 unit low in its box in the reference; in the lockup it is
  aligned to the wordmark's x-height band, not its box center.

### B. Section illustrations (ChatGPT)

- B1. Four images, one per course group, in the mascot's style: thick navy outline, flat periwinkle
  and mint fills, soft blush accents, cream background, no text, no logos, no real products.
- B2. Prompts (each prefixed with a shared style line and the reference image attached):
  - Shared style: "Flat sticker-style illustration, thick dark navy outlines, palette limited to
    periwinkle blue, mint green, white and a soft pink blush, plain warm cream background, no
    text, no letters, no logos, 3:2 landscape, generous empty margin. Same character as the
    attached mascot."
  - Group 1, Read a small program: "The mascot tracing one line of a short paper printout with a
    finger, a few small boxes holding values floating beside it."
  - Group 2, Navigate a repository: "The mascot standing on a simple folder tree drawn like a
    map, holding the magnifying glass over one file, a dotted path linking three files."
  - Group 3, Follow a web request: "The mascot watching an envelope travel along a pipe through
    three small gates toward a server box, one gate showing a check mark."
  - Group 4, Reason about systems: "The mascot at a small control desk with connected gears, a
    storage drum and a flowing stream of dots between them."
- B3. Process: I drive ChatGPT in the owner's Chrome. Approving this document approves sending
  these four prompts and downloading the four results. Any regeneration uses the same prompts with
  a one-line correction.
- B4. Files are converted with sharp to WebP at 480 and 960 wide and stored in
  `web/public/learn/group-<n>-{480,960}.webp`. They render with explicit `width`, `height` and
  `aspect-ratio: 3 / 2`, so loading never shifts the layout. Below the fold they load lazily.
- B6. Generation is the lead's task and runs while the pages are built. Builders work against
  the reserved 3:2 plate with no image; `--plate` starts as the reference's cream and is
  re-sampled when the images land.
- B5. The plate is a fixed cream surface (`--plate`, an OKLCH value sampled from the images) with
  the concentric radius rule. Images are decorative, with empty `alt`; the group title carries the meaning.

### C. Learn catalog (`/learn`)

- C1. **Header.** Title, a one-sentence lede capped at 60ch with `text-wrap: balance`, the full
  mascot at the right (hidden under 640px).
- C2. **Continue panel.** One panel directly under the header: a progress bar (completed of
  total), the count in tabular numbers, and one primary button naming the next lesson. Its height
  is reserved before progress loads, with the button present from first paint.
- C3. **Where to start.** The paragraph becomes three choices in a row: "New to code" (L01),
  "Comfortable with small programs" (L07), "Comfortable in a repository" (L13). Each is a link.
- C4. **How it works** shrinks to three short facts on one line each, no card.
- C5. **Groups are sections, not cards.** Each group has its illustration plate, a group number,
  the title, the summary and its own "n of m" progress. Illustration left on desktop, alternating
  sides is not used (it reads as a template); on mobile the plate sits above.
- C6. **The path.** Inside a group, modules run down a vertical rail. Each lesson is a node on the
  rail and a row: code (monospace, tabular), title, minutes. The node shows the state: empty,
  in progress (half ring), complete (check), updated (dot with a label). Checkpoints and the
  capstone are larger milestone nodes with their badge.
- C7. The whole row is the link, at least 44px tall, with no dead gap between rows. The summary
  sits under the title in muted text, one line, truncated with the full text on the lesson page.
- C8. A sticky group index on screens 1100px and wider lists the four groups with their progress
  and marks the one in view.
- C9. Rows enter with a stagger of `--motion-stagger` (45ms), capped at the first six rows in view, once.
- C10. Status slots keep a fixed width so nothing jumps when progress fills in.
- C11. The "Suggested first: …" line is removed from every row; the rail shows the order. The
  prerequisite stays on the lesson page. "Nothing is locked" is said once, beside C3.
- C12. The Continue panel's button sits above the fold at 1440 by 900 and at 375 by 812 (today it
  is about 400px down, under the explainer).
- C13. Rows fill the content width; the 350px of dead space at the right of each row goes to the
  sticky index (C8) on wide screens.

### D. Lesson page (`/learn/[slug]`)

- D1. The lesson code and title morph from the catalog row into the page header (shared element
  transition, section G16).
- D2. Prose measure is 68ch; paragraphs use `text-wrap: pretty`, headings `balance`.
- D3. A compact section index under the header (Outcome, Example, Checks, Next) as anchor links.
- D4. Exercise choices: selecting shows at once (optimistic, local). "Check" shows a busy state and
  the result only after the server answers. A failed request restores the previous state and says so.
- D5. After a server-graded correct answer, the lesson's status and the catalog progress update at
  once from the response, without waiting for a refetch.
- D6. Previous and next lesson links at the foot. On mobile they sit in a bar padded with
  `env(safe-area-inset-bottom)`.
- D8. The worked example's `<details>` gets a boxed summary with a chevron that rotates, at
  least 44px tall, so it reads as a control.
- D9. "Check" is the one primary button once a choice is selected, and visibly inactive before.
  "Show a hint" and "Show the answer" are quiet buttons.
- D10. Choice rows: the radio is centered on the label's first line, and the whole row is the target.
- D7. Inline code inside prose is sized with `font-size-adjust` so its x-height matches the body text.

### E. Challenges (`/challenges`)

- E1. **Layout.** Desktop: two equal-height columns. Left: the three challenge bars stacked.
  Right: the streak panel. Under 900px: bars, then streak. "How challenges work" becomes a
  closed disclosure across the full width underneath.
- E2. **A challenge bar** holds four things in one row: the type (icon and "Daily", "Weekly" or
  "Monthly"), "Ends in" with the countdown in tabular numbers, the points (50, 100 or 200, so the column fits "+200 pts"), and a
  Start button. Column widths are fixed across the three bars so the columns line up.
- E3. Button states: "Start" (primary) when not started or signed out, "Continue" when attempted,
  "Completed" with a check (quiet) when done or solved before the period. A withdrawn puzzle shows
  "Withdrawn" with no button.
- E4. Dropped from the bar: puzzle title, difficulty and type chips, repository, rotation text,
  state note, achievements line. The rotation text and `LocalRotation` move into the disclosure.
- E5. **Streak panel.** Heading "Daily streak". The current streak as a large tabular number.
  A bar filled to the current streak, its fill interpolated in OKLCH. Its scale ends at the
  longest streak, and never below 7. When the current streak is the longest, the scale ends at
  the next milestone above it from 7, 14, 30, 60, 100, 200, 365, labeled "Next: 14 days". These
  are display milestones only, not achievements.
- E6. **Calendar.** The last five weeks as a 7-column grid, Monday first, UTC days. A completed
  day is filled, today has a ring, future days are faint. Each cell has an accessible label.
- E7. **Stats row.** Current, Longest, Daily completed, Weekly completed, Monthly completed. No
  explanatory paragraph (the rule moves into the disclosure).
- E8. Data: `ChallengeStreak` gains `recentDays: string[]`, the completed UTC dates in the last 35
  days, taken from the query `getChallengeStreak` already runs. No new query, no migration.
- E9. Signed out: the right column shows the mascot, one sentence and the sign-in button, at the
  same height as the bars.
- E10. The loading skeleton mirrors the new layout exactly.
- E11. `TodayStrip` on `/puzzles` is unchanged.
- E12. Baseline to beat: today the lower row leaves a 232px hole under the left column, and a
  two-line puzzle title pushes one card's contents 24px lower than the others.

### F. Buttons and motion (site-wide, `globals.css`)

- F1. Press: `transform: scale(0.97)` on `:active`, 160ms, the existing `--motion-feedback` curve.
  Transitions list their properties; never `transition: all`.
- F2. Hover styles sit inside `@media (hover: hover) and (pointer: fine)`, so touch never sticks.
- F3. Origin-aware press: on `pointerdown` a primary button records the pointer position in two
  custom properties, and a radial highlight spreads from that point once (300ms). One small shared
  client helper; without JavaScript the button still works.
- F4. Buttons that move forward ("Start", "Continue", "Next") carry an arrow icon that slides 2px on hover.
- F5. Busy buttons swap their icon through `SwapIcon` and keep their width.
- F6. Menus and popovers (account menu, theme picker) scale from 0.96 with `transform-origin` at
  the corner nearest their trigger.
- F7. Small controls get a 44px hit area through a pseudo-element without growing visually.
- F8. All of it is off under `prefers-reduced-motion`, keeping the color feedback.
- F10. Header navigation links, the logo link and the sign-in button reach 44px tall on touch
  screens (today 30 to 36px).
- F9. The workspace's Monaco, tree targets, editor tabs and splitters are untouched.
- F12. Scope of F2 and F7: `globals.css` (so every `.btn` gets F1 and F2, including in the
  workspace) and the Learn, Challenges and site-header stylesheets. The workspace's own
  stylesheets (`puzzle`, `hints`, `markdown` modules) are not edited.

### G. The sixteen craft details

| # | Detail | Where and how |
|---|---|---|
| G1 | Kerning | `font-kerning: normal` on body; `text-rendering: optimizeLegibility` on display headings only; wordmark paths kerned by hand. |
| G2 | Optical center | Mascot in the lockup (A8); arrow and check icons nudged in buttons; the streak number aligned by cap height. |
| G3 | Tabular numbers | Countdowns, points, streak, stats, progress counts, lesson codes and minutes. |
| G4 | Layout shift | Reserved heights for progress, status slots, images with dimensions, skeletons that match. Target CLS 0 on both pages. |
| G5 | Tracking | Page titles -0.015em (as now), section and module titles -0.01em (today untracked, so the scale is uneven), body 0, small labels +0.01em. Defined as tokens. |
| G6 | Optimistic updating | D4 and D5. Never for a graded result. |
| G7 | x-height | D7, and the same for inline code in lesson rows. |
| G8 | Touch target | C7, F7. Minimum 44px on touch screens. |
| G9 | Origin-aware animation | F3, F6. |
| G10 | OKLCH | Mascot and plate colors, streak bar interpolation, calendar fills via `color-mix(in oklch, …)`. New values live in the stylesheet, not in theme tokens, because the pre-paint script accepts only hex and `rgb()`. |
| G11 | Widow | `text-wrap: balance` on headings, `pretty` on paragraphs, non-breaking space in "5 min" and "+50 pts". |
| G12 | Safe area | D6, and the page's side padding uses `max(16px, env(safe-area-inset-left/right))`. The lead adds `viewportFit: "cover"` to the viewport export, which is not set today, and checks every page's edges on a notched phone size. |
| G13 | Stagger | C9. 45ms, six items at most, once. |
| G14 | Line length | 68ch for prose (lesson paragraphs measure about 97 characters today), 60ch for ledes. |
| G15 | Interruptible animation | State changes use transitions, not keyframes, so a reversed hover or press retargets mid-way. |
| G16 | Shared element transition | `ViewTransition` with `name={"lesson-" + slug}`, `share="morph"`, `default="none"` on the row title and the lesson header. Unique names per row. Pointer events stay live during the transition. Off under reduced motion. |

### H. Removing themes that clash with the plates

- H1. A script renders every theme's page background, raised surface and accent beside the cream
  plate and mascot colors, and scores each theme.
- H2. Proposed test, to be tuned on the contact sheet: a theme clashes when its page background is
  strongly colored (OKLCH chroma of `--bg` at or above 0.06) or when its background hue sits
  opposite the plate's warm hue at chroma above 0.03.
- H3. The failing list and a contact sheet go to the owner before anything is removed.
- H4. Removal is an exclusion list with a reason in the theme derivation, then
  `UPDATE_THEMES=1 npx vitest run tests/themes.test.ts` regenerates the catalog and `MAPPING.md`.
- H5. A saved preference or favorite naming a removed theme falls back to the default theme, on
  the server, in the controller and in the pre-paint cache. A test covers each.
