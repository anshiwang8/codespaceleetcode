# CLAUDE.md

Operational rules for working in this repo. Read `spec.md` before any non-trivial change. The spec is the source of truth; if code and spec disagree, stop and flag it.

## Project

The site is named **codebases**. LeetCode-style puzzles set inside real open-source repos pinned to a commit. v1 has four puzzle types: Find, Trace, Architecture, and Design (a system-design interview question answered from a real implementation, spec section 2). Users navigate code in a browser IDE and submit a precise answer, which is graded server-side against a canonical answer key.

## Layout

- `web/` is the Next.js App Router app (TypeScript strict), deployed on Vercel.
- `ingest/` is the Python pipeline (uv): clone, filter, SCIP index, upload to R2, seed, validate.
- `content/` holds `repos.yaml`, `schema/`, `puzzles/<repo-slug>/<id>.yaml`, `solutions/<id>.md`, and `blind-attempts.json` (each blind solver's first graded result).
- `supabase/migrations/` holds SQL migrations. Never edit an applied migration; add a new one. Hosted Supabase gives clients every privilege on a new table or sequence, so a migration that adds one must enable RLS, revoke `anon` and `authenticated`, and grant back only what clients may read. `web/tests/rls.test.ts` checks this.
- `supabase/local/shim.sql` adds what hosted Supabase provides, for the local database only.
- `web/app/(marketing)/page.tsx` is the static landing page at `/`, and must render without the database. `web/app/(app)/` holds every page under the site header, including the puzzle list at `/puzzles`.
- `web/components/puzzle/Markdown.tsx` renders prompts, hints and solutions: GitHub-flavored Markdown with raw HTML dropped, and fenced `mermaid` blocks drawn by `MermaidDiagram.tsx`. Mermaid runs with `securityLevel: "strict"` and a `secure` list so a diagram can't change its config or inject CSS. Never loosen either.
- `web/lib/server/better-auth.ts` configures Better Auth (GitHub sign-in, sessions in the `auth_*` tables from migration 0005). Change its table or column names only together with a migration. `getCurrentUser` in `web/lib/server/auth.ts` is the one place pages and routes learn who's signed in: a Better Auth session first, then the localhost-only dev login. Keep the origin check on, account linking off, and the token and user-editing routes in `disabledPaths`; `web/tests/github-auth.test.ts` runs a real sign-in through the callback to check all of it.
- `web/lib/server/profile.ts` builds the profile (`/profile`, `/api/me/profile`, `/api/me/activity`, `/api/me/history`). Every query is scoped to the signed-in user's id and joins `puzzles` with `published`, and aggregates in SQL (daily counts, streak runs, first solves): never send raw submissions to the browser or query per date. The UTC date of `now` on the server is the one day boundary for the calendar, its counts and the streaks. `web/lib/activity.ts` lays the calendar out and words each date; its intensity thresholds (0, 1, 2–3, 4–6, 7+) are fixed. It never selects the stored email, `auth_users.image`, tokens, submitted answers or solutions.
- `web/lib/themes/` holds the themes: `tokens.ts` (the typed token registry), `derive.ts` (palette to tokens, with the contrast rules), `names.ts` (original names for the adapted presets), `runtime.ts`, `prepaint.ts` (the inline first-paint script) and `controller.ts` (preview, apply, favorites, account versus browser). `catalog.generated.ts` and `docs/themes/MAPPING.md` are generated by `web/tests/themes.test.ts`: run `cd web && UPDATE_THEMES=1 npx vitest run tests/themes.test.ts` after changing derivation, names or the default tokens, and never edit them by hand. Every theme must pass that test's contrast checks; fix the derivation, never loosen a target. Colors in components come from tokens, never hard-coded, so every theme applies. Monaco and Mermaid restyle on the `codebases:theme` event without remounting. The pre-paint script only applies token-named properties with hex or `rgb()` values; keep it that strict.
- `web/app/(app)/settings/` and `web/components/settings/` are the account settings. `web/lib/profile-fields.ts` validates profile fields and links for both browser and server; `web/lib/server/settings.ts` saves them. `web/lib/server/avatar.ts` re-encodes pictures with sharp from an allowlist of decoded formats; never serve an upload's original bytes or let anyone but its owner read it. `web/lib/server/email.ts` runs contact email confirmation (hashed, single-use, expiring tokens bound to user and purpose) and `email-delivery.ts` sends through Resend or the local outbox. The contact email never appears in `/api/me`, the profile, logs or errors, and the user-managed fields are never overwritten from GitHub. Better Auth's user-editing routes stay disabled.
- `web/components/site/Avatar.tsx` is the one avatar: the user's own picture, or the white silhouette on gray. Never use GitHub's avatar.
- `web/app/globals.css` holds the design tokens and shared controls. Use them instead of new hard-coded colors or sizes. The puzzle workspace keeps its denser sizing in `components/puzzle/puzzle.module.css`; check its height and nested scrolling after changing anything shared.
- `web/lib/format.ts` formats dates and numbers, always with `en-US`, and dates in UTC, the zone the profile groups activity by.
- `web/lib/api-types.ts` holds the API response shapes the routes and UI share.
- `web/lib/topics.ts` holds the topic list's labels and descriptions. Its slugs must match the `tags` enum in `content/schema/puzzle.schema.json`, and a web test checks this.

## What's left, and manual steps

`spec.md` section 14 is the launch checklist. **Manual** items (M1–M9 and per-developer setup) need a person with an account, a payment method, or a decision: domains, Supabase, the GitHub OAuth apps, Vercel, Cloudflare R2, human blind solves, legal review, branch protection. You can't do these. When a task depends on one, tell the user which item it is and give them its steps from section 14, then stop instead of working around it. **Code** items (C1–C9) are open to pick up; use their numbers in PR titles and DEVLOG entries.

Never ask for a secret in chat, put one in a command, or print one. Secrets live only in `web/.env.local`, `ingest/.env`, or the Vercel and Cloudflare dashboards. If one appears in chat or terminal output, tell the user to regenerate it at its source.

When a checklist item lands, mark it done in section 14 in the same change, along with its DEVLOG entry.

## Non-negotiable rules

1. **Answer keys never reach the client.** `answer_json` and solutions are read only in server routes through the server-side database connection (`pg` with `DATABASE_URL`, in every environment). No answer data in props, page payloads, logs sent to the browser, or error messages. RLS denies client reads on `puzzles.answer_json` and `solutions`.
2. **Answers are canonical IDs.** Files are `path`, symbols are `path#Qualified.name[~N]`, locations are `path:Lstart-Lend`. The grader compares IDs. Never add fuzzy matching, string similarity, case-insensitive matching, or LLM grading.
3. **Users select answers, never type them.** Every answer input in the UI is built from clicks on the tree, symbols, or lines.
4. **Snapshots are immutable.** Never change the SHA of an existing snapshot. A newer commit means a new snapshot.
5. **Every puzzle passes `pnpm validate`.** Never weaken a validator check to get a puzzle through. Use `validator_overrides` with a written reason, and only when the check is a false positive.
6. **Uniqueness is fixed in the prompt, not the key.** If a puzzle has two plausible answers, tighten the prompt's scope. Only add to `accept` for truly equivalent answers (e.g. a re-export of the same function), with a reason in `accept_reasons`.
7. **Code intelligence comes from SCIP.** Don't substitute name-based matching for definitions, references, or call edges. One narrow exception: scip-typescript leaves top-level `root.name = function () {}` undefined, so `ingest/src/ingest/convert.py` promotes those methods using SCIP's resolved root and the assignment syntax at that exact position. References still come only from SCIP's own locals, never from a name lookup. tree-sitter also answers position-only questions: whether a reference at a given spot is a type, decorator or base class, and whether a Python reference sits on a `def` or `class` name.
8. **v1 scope only.** No code execution, bug-fix puzzles, or AI mode. If a task needs them, stop and flag it. Build puzzles (users write code that tests grade) are the v2 plan in spec section 15; build none of it until its open decisions are made and this rule and rules 2 and 3 are changed in the same change.

## Conventions

- TypeScript strict, no `any`. Validate route inputs with zod.
- Server-only modules go in `web/lib/server/` and import `server-only`.
- Python: type hints, `ruff` + `pyright` clean. Run with `uv run`.
- Puzzle IDs: `<repo-short>-<type>-<nnn>`, e.g. `hono-trace-002`.
- One concept per puzzle. If the prompt needs "and", split it.
- A Design prompt opens with `Interview question:`, the system and the one requirement, then names the file or function and asks one question whose answer follows from the code (spec section 2). Its solution also says what a strong interview answer would add: the trade-off and the usual alternative.
- A solution follows the format in spec section 4. Every quoted code line and `path:line` reference must hold at the pinned SHA, and it must not name another puzzle's answer: its symbol, file or line, or most of its set or sequence.
- Write everything the project owns in US English: UI copy, labels, errors, puzzle titles, prompts, hints, choice labels, solutions, docs and comments (behavior, color, organize, canceled, license). Auth actions are "Sign in" and "Sign out". Leave upstream code, quoted source, identifiers, paths, slugs and IDs exactly as they are.
- User-facing empty and error states say what happened and what to do next. They never show setup commands.
- Landing and marketing copy states only what the product does and what's true now. No trend claims, counts, testimonials or logos without a source. Examples quote real puzzles but never show a puzzle's answer; the worked example's answer must not be any puzzle's answer (`web/tests/landing.test.ts`).
- Motion goes through the tokens and global keyframes in `app/globals.css`, stays finite, and is off under reduced motion. The single bounce is the correct-result ✓ (`.resultCheck`). Don't add looping, floating or bouncing elsewhere, and never animate Monaco, tree targets, editor tabs or splitters.
- Rate difficulty by the rules in spec section 4, and tag each puzzle with 1 to 3 topics from the fixed list there.

## Testing

- Grader: unit tests for every answer kind, including wrong file, wrong order, extra/missing set members, selection outside the window, and anchor not covered.
- Validator: fixture puzzles that must pass and fixture puzzles that must fail, one per check.
- API: tests that `/api/puzzles/:slug` and errors from `/submit` never contain answer data.
- e2e (Playwright): solve one puzzle of each type end to end against a fixture snapshot.
- Run the full suite before marking any task done.

## Commands

Fill these in as they are created:

From the repo root:

```
pnpm local               # database, seed, site at http://127.0.0.1:3000 (PORT changes the port). Needs snapshots: see README.md on a fresh clone
pnpm db                  # start local Postgres, apply migrations (stays running). LOCALDB_PORT changes its port, and pnpm dev, the tests and ingest seed follow it
pnpm db:reset            # delete all local database data
pnpm dev                 # web app, bound to 127.0.0.1 because dev login trusts the Host header
pnpm test                # all unit tests: test:ingest, then test:web. Web tests fail without pnpm db running or TEST_DATABASE_URL; ALLOW_NO_DB=1 skips the database ones
pnpm --filter web lint
pnpm --filter web typecheck   # plain tsc needs next typegen first
pnpm --filter web build
pnpm visual:review       # isolated headless screenshot gallery + motion checks; see VISUAL_REVIEW.md
pnpm e2e                 # Playwright. Starts its own database and server, and can run beside pnpm dev
pnpm validate            # every check in spec section 6
```

From `ingest/`:

```
uv run python -m ingest snapshot <slug>   # fetch, filter, index, write to ingest/out/ (no upload yet)
uv run python -m ingest snapshot-all [--force]   # every repo in repos.yaml. --force after any pipeline change, since finished snapshots are skipped
uv run python -m ingest seed [--force]    # validate, then load snapshots and puzzles into Postgres
uv run python -m ingest blind-export --out <file> [--repo <slug>]   # puzzles with only what a solver may see
uv run python -m ingest blind-check <answers.json> --solver <name> [--write]   # grade a blind solve; prints pass or fail, never the key. One graded attempt per solver per puzzle version
uv run python -m pytest         # always `python -m`: Windows Application Control can block generated .exe launchers
uv run ruff check .
uv run ruff format --check .
uv run pyright
uv run python scripts/gen_proto.py            # regenerate SCIP bindings from the vendored scip.proto
uv run python scripts/regen_fixture_index.py  # rebuild the test fixture's index after changing it
```

From `web/`:

```
UPDATE_THEMES=1 npx vitest run tests/themes.test.ts   # regenerate the theme catalog and docs/themes/MAPPING.md
```

`INGEST_TEST_DB_URL` turns on the seed tests. It's separate from `SUPABASE_DB_URL`, so tests can't touch a real database.

`content/schema/grading-cases.json` is run by both the web and Python test suites, so the two graders can't drift apart. Add new grading rules there.

Snapshots need the indexers on PATH: `npm install -g @sourcegraph/scip-typescript@0.6.0 @sourcegraph/scip-python@0.6.8`.

Platforms: developed on Windows, and also run on macOS (Apple silicon, Node 26). Install pnpm with `npm install -g pnpm@12.6.0` when corepack isn't available. `pnpm-workspace.yaml`'s `allowBuilds` must set the `@embedded-postgres/<platform>` package to `true` on macOS and Linux, since its install script links Postgres's libraries; an unlisted package makes `pnpm install` fail. Windows runs with it set to `false`. Scripts that spawn `pnpm` need a shell only on Windows. Playwright's Desktop Chrome profile reports a Windows user agent, so Monaco uses Ctrl as its click modifier in e2e even on macOS.

## Environment

Split per package and documented in each `.env.example`; never commit real values. R2 write credentials must never appear in `web/`.

`web/.env.example`:

```
NEXT_PUBLIC_SNAPSHOT_CDN_URL=
BETTER_AUTH_SECRET=
BETTER_AUTH_URL=
GITHUB_CLIENT_ID=
GITHUB_CLIENT_SECRET=
DATABASE_URL=
SNAPSHOT_DIR=
DEV_AUTH_TEST_HOST=
TEST_DATABASE_URL=
RESEND_API_KEY=
EMAIL_FROM=
DEV_OUTBOX_DIR=
```

`RESEND_API_KEY` and `EMAIL_FROM` turn on real email (M10); they belong only in `web/.env.local` or Vercel. Without them, outside production, email goes to `DEV_OUTBOX_DIR` (default `web/.dev-outbox/`); in production, Settings says email is unavailable. None of these are needed on localhost: `DATABASE_URL` and `SNAPSHOT_DIR` have local defaults outside production, and without `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` GitHub sign-in is simply off. Production refuses to start without `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`. The server reaches the database only through `DATABASE_URL`; Better Auth uses the same pool.

`ingest/.env.example`:

```
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET=
SUPABASE_DB_URL=
```
